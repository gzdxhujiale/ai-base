# 设计原则

## 范围

本文定义工作台原型长期适用的体验与视觉不变量；某个功能的具体交互属于 `design-docs/`，组件实现方式属于 `FRONTEND.md`。

## 设计目标

现有工作台把“我在哪里、能做什么、下一步去哪里”放在首位：稳定导航提供定位，命令搜索缩短入口路径，AI 以邻近工作流的入口出现。该方向来自当前壳层和 `design-docs/core-beliefs.md`，不等于已验证的生产体验。

## 核心原则

- **定位先于装饰。** 当前页面、导航选中态和面包屑必须一致，让用户可见地知道位置与可行动作。
- **可发现性不能因压缩布局而消失。** 收起侧边栏用 Tooltip 保留名称；搜索同时提供显式入口和 `⌘/Ctrl + K` 快捷键。
- **状态诚实且可恢复。** 空、禁用、加载、失败或未接线能力都应说明其状态；AI 抽屉不能暗示已连接企业知识库。
- **一致性优先于局部炫技。** 新模式仅在改善任务效率时引入，并优先复用 Arco 与已有 token。

## 信息与操作层级

- 顶部栏承载跨页面入口：工作台返回、企业、搜索、AI 与用户菜单。
- 侧边栏承载主要工作区；“企业设置”与前六个主导航项通过分割线区分。
- 主内容区显示当前位置和该页面内容。主要操作应保持视觉上可辨；当前仅有导航与入口原型，不应为占位页虚构业务操作层级。

## 交互与状态

- 导航跳转应更新 URL；命令搜索跳转后关闭 Modal。
- 键盘快捷键要阻止浏览器默认搜索并触发命令搜索。新增键盘交互时保持可见焦点与可访问名称。
- 当前已实现：AI 输入为空时发送按钮禁用、建议问题填入输入框、抽屉/搜索可显式关闭。
- 尚未建立统一的加载、无结果、提交中、失败、权限不足或离线模式。接入异步能力时，具体状态设计应写入相关 `design-docs/`，并遵循 `RELIABILITY.md`。

## 设计系统事实

| 项目 | 当前来源 |
| --- | --- |
| 组件与图标 | `@arco-design/web-react` 与 `@arco-design/web-react/icon` |
| 布局和响应式 | Tailwind CSS v4 工具类 |
| token 与全局覆盖 | `src/index.css` |
| 品牌/高亮/页面色 | `#165DFF`、`#EFF5FF`、`#F6F8FB` |
| 字体 | `src/index.css` 中的中文优先 `--font-sans` |

`src/UI/` 为 Input、Modal、Button 等已有跨功能封装添加项目 class；重复的复杂视觉模式再提炼为封装或共享 CSS，不为单一页面复制近似 token。

## 响应式与可访问性

当前策略是桌面显示固定顶部栏与可折叠侧边栏，小屏隐藏侧边栏并把搜索切换为图标入口。AI 按钮在小屏隐藏。现有代码已为部分图标按钮提供 `aria-label`，但没有系统性的读屏或键盘测试；不要声明特定无障碍合规等级。

## 反模式

- 用静态演示内容伪装已连接的任务、成员、经营数据或 AI 回答。
- 在已有 Arco/项目模式可用时新增近似颜色、圆角或自定义控件。
- 仅靠颜色表达当前页、禁用或操作后果。
- 为未实现异步能力制作看似成功的反馈。
