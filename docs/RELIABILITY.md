# 可靠性

## 当前状态

当前应用为纯前端原型，没有网络请求、服务端状态、持久化、错误边界或监控配置。刷新页面会丢失侧边栏、搜索和 AI 抽屉状态。

## 可靠性目标

- 路由切换不应导致整页刷新或丢失未提交输入。
- 异步数据应有加载、空、失败和重试状态。
- AI 请求应支持取消、超时、流式中断和重新提交。
- 关键操作应具备幂等性，错误后可以安全恢复。
- 发布后应能观测前端错误、API 延迟、AI 成功率和用户可用性。

## 建议措施

接入服务端后引入统一 API client、错误边界、请求超时与重试策略；按租户和用户维度记录不可包含敏感正文的审计事件；为核心导航、搜索和 AI 提交流程建立端到端检查。
