# 可靠性契约

## 当前可靠性模型

当前应用是没有网络依赖、服务端状态或持久化的浏览器端原型。路由切换由 TanStack Router 在客户端完成；侧边栏、命令搜索、抽屉和 AI 输入的状态都在内存中，刷新后丢失。没有错误边界、监控、日志、健康检查或自动化测试。

本文不定义未来 API、超时、重试或 SLO；这些尚无仓库证据。接入异步能力前必须先为其建立具体契约。

## 当前不变量

| 不变量 | 当前依据 | 执行方式 |
| --- | --- | --- |
| 未知页面 ID 不渲染空页面。 | `WorkspaceShell` 回退到第一个导航项。 | 当前代码；无自动化测试。 |
| 导航与命令搜索跳转不应触发整页刷新。 | TanStack Router 与 `navigate`。 | 当前代码；无自动化测试。 |
| 不把未接线的 AI 入口表示为成功完成的请求。 | 发送按钮没有提交处理。 | 当前 UI 与设计文档。 |

## 异步能力接入前的契约要求

对未来 API、数据查询或 AI 流式响应，实施前应在相关产品/设计文档和 ExecPlan 中明确：

- 用户可见的加载、空、成功、失败、取消和重试状态；
- 失败是否可重试、重试由谁触发，以及不能安全重试的情形；
- 提交中断或刷新后的恢复/丢失语义；
- 有副作用操作的幂等性与重复提交处理；
- 错误是否暴露给用户、哪些细节仅可记录；
- 所需测试和可观测性证据。

TanStack Query 的当前全局查询选项（30 秒 staleTime、失败重试一次）不是应用级重试策略，因为还不存在任何 query。

## 已知缺口

- 没有用于渲染异常的错误边界。
- 没有远端请求，因此没有超时、取消、离线、部分失败或缓存失效模型。
- 没有前端错误监控、指标、追踪或日志规范。
- 没有测试来防止路由、快捷键或状态回归。

这些是生产化前的设计与实施工作，而非可从当前代码推断出的运行承诺。优先级见 `QUALITY_SCORE.md` 与 `exec-plans/tech-debt-tracker.md`。

## 验证

当前可执行基线是 `pnpm build`；`pnpm lint` 是预期检查但因 `.vitepress/cache` 生成文件的配置问题无法通过。新增可靠性行为时，必须提供实际可运行的验证命令或明确记录缺口。
