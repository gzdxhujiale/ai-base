# 复杂工作计划协议

## 用途

本文定义 ExecPlan 的写作和维护协议，不是项目路线图。具体计划仅位于 `exec-plans/active/` 与 `exec-plans/completed/`；当前技术债务清单见 `exec-plans/tech-debt-tracker.md`。

## 何时创建 ExecPlan

在下列工作开始前创建计划：跨多个模块的大功能、架构或服务边界变化、大型重构、迁移、需要多阶段验证的高风险工作，或存在实质不确定性的任务。文案修正、局部样式调整和能在单一模块中安全验证的小改动通常不需要计划。

当前仓库在引入认证、租户/权限、真实 API/数据层、AI 服务或测试体系前都需要 ExecPlan，因为这些能力尚无已实现契约。

## 计划位置与生命周期

```text
docs/exec-plans/
├── active/      # 已批准或正在执行
└── completed/   # 已完成并复盘的计划
```

开始时在 `active/` 新建 Markdown 文件；执行中持续更新；完成后先更新持久知识文档和质量评分，再移入 `completed/`。计划本身是实施历史，不替代架构、设计、安全或可靠性契约。

## 每份计划的必要内容

1. **目的与范围：** 完成后可观察到的结果、非目标与依赖。
2. **上下文：** 相关模块、路径、术语与当前行为，使没有会话历史的执行者能理解任务。
3. **Progress：** 真实状态的 checklist，区分完成、部分完成和剩余工作。
4. **实施顺序：** 说明为何按该顺序改哪些模块；Concrete Steps 应给出工作目录、命令和预期可观察结果。
5. **验证与验收：** 用“给定/当/观察到”描述行为，并列出真实命令。
6. **风险、幂等性与恢复：** 对有副作用的操作说明重试、回滚、清理或停止条件。
7. **Surprises & Discoveries：** 记录意外行为、缺陷或证据。
8. **Decision Log：** 对重要决定记录日期、选择与理由。
9. **Outcomes & Retrospective：** 记录完成项、未完成项、遗留债务和需要沉淀到长期文档的知识。

## 当前仓库的验证基线

应用代码使用 `pnpm lint` 与 `pnpm build`；文档站使用 `pnpm docs:build`。当前没有测试脚本。计划不得承诺不存在的测试、部署或监控能力；若新增这些能力，须把实际命令和验收纳入计划。

## 关联与维护

- 架构边界改变：更新 `../ARCHITECTURE.md`。
- UI/产品行为改变：更新 `DESIGN.md`、`PRODUCT_SENSE.md` 和需要的具体设计/产品规格。
- 安全或失败模型改变：更新 `SECURITY.md`、`RELIABILITY.md`。
- 完成重大改善或发现新债务：更新 `QUALITY_SCORE.md`。

不要把一次性聊天上下文、未经验证的假设或完整 Skill 流程写入计划。
