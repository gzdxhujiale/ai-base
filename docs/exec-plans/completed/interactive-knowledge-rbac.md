# 交互式知识空间与 RBAC 原型

## 目的与范围

在现有纯客户端工作台中实现角色视图切换、企业/个人知识空间、知识库与文档生命周期、企业设置和演示 RBAC。范围仅限浏览器内存状态；不引入认证、后端、持久化、真实解析或真实授权。

## 上下文

入口位于 `src/features/workspace/WorkspaceShell.tsx`。领域状态位于 `src/stores/knowledge-store.ts`，知识空间与企业设置页面分别位于 `src/features/knowledge/` 和 `src/features/enterprise-settings/`。

- [x] 实现企业/个人空间、上传状态模拟及文档生命周期操作。

## 实施顺序

1. 先建立单一内存状态，保证知识空间与设置页看到同一份数据。
2. 接入知识空间，再将角色状态接入工作台壳的导航、用户菜单和内容路由。
3. 完成企业设置的 RBAC、归档和回收站入口。
4. 用 `pnpm lint` 与 `pnpm build` 验证，无自动化测试时手动检查角色切换与状态变化。

## 验证与验收

- 给定员工角色，观察到企业设置隐藏，企业空间只显示获授权知识库，个人空间可管理自己的文档。
- 给定管理者角色，观察到仅能管理预置的产品知识库和其中的文档。
- 给定经营者角色，观察到可创建/编辑/归档知识库、配置成员角色及知识库权限。
- 当选择 MD 或 DOCX 文件，观察到文件名进入列表并依次展示上传、解析和就绪状态。
- 当删除或归档内容，观察到其进入统一回收站或已归档列表并可恢复。
- 在仓库根目录运行 `pnpm lint` 与 `pnpm build`。

## 风险、幂等性与恢复

所有变化仅在前端内存中，刷新即恢复初始演示数据。模拟计时器只变更当前内存文档状态；不存在外部副作用或清理步骤。

## Surprises & Discoveries

- `pnpm` 需要读取用户级配置，因此验证命令必须在受批准的沙箱外运行。
- 环境未提供 `agent-browser` 命令，无法执行预期的自动化浏览器截图检查；已通过 lint 和 Vite 生产构建验证。

## Decision Log

- 2026-08-17：成员显式撤销优先于显式授权与部门继承；本期 UI 先展示原则与知识库级授权。

## Outcomes & Retrospective

已完成内存态角色视图、知识空间、文档生命周期、回收站和知识库级 RBAC 配置。`pnpm lint` 与 `pnpm build` 均通过。仓库仍无自动化测试运行器，且此环境缺少浏览器自动化命令；手动浏览器验证留作后续质量缺口。
