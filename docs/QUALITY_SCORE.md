# 质量记分卡

> 基于当前代码、配置与文档快照的工程评估，不代表生产就绪认证。

## 评分方式

| 分数 | 含义 |
| ---: | --- |
| 5 | 有清晰边界、自动化保障和可验证运行证据。 |
| 4 | 整体健康，仅有小且已知的缺口。 |
| 3 | 可维护的基线，仍有明显保障缺口。 |
| 2 | 存在影响扩展或用户体验的显著债务。 |
| 1 | 脆弱或缺乏必要保障。 |
| 0 | 能力缺失或无法可靠评估。 |

分数基于当前证据，不表示历史趋势；重大功能、架构、安全/可靠性事件或债务清理后应重新评估。

| 领域 | 分数 | 证据 | 主要缺口 |

## 优先质量缺口

1. **测试为 0：** 在扩展路由、搜索、状态或异步行为前，引入并执行适合的组件/路由与关键流程验证。
2. **原型闭环未完成：** AI 发送、业务页面与真实数据/权限都未实现；见 `exec-plans/tech-debt-tracker.md`。
3. **Lint 基线失效：** 排除或清理 `.vitepress/cache` 的生成依赖，使 `pnpm lint` 只检查受维护源码。
4. **生产横切能力缺失：** 认证、授权、错误处理和可观测性需要先有明确服务契约，而不是直接接线。

## 更新政策

只在可观察证据变化后更新分数：实现/移除重大能力、引入测试或自动检查、处理可靠性/安全事件，或完成明确的债务清理。具体改进任务应写入 ExecPlan，而不是在本文展开实施步骤。
