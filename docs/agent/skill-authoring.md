# Skill 编写与维护

## 何时创建

仅当一种专门任务会重复出现、需要一致步骤/工具/验证，并且现有 `AGENTS.md`、知识文档或自动检查无法恰当承载时，才创建仓库 Skill。当前项目已有 UI/设计系统 Skills；不要为单次功能开发建立 Skill。

## 结构与范围

Skill 放在 `.agents/skills/<skill-name>/SKILL.md`。`SKILL.md` 应包含可匹配的 name 与 description，并只描述该工作流的输入、必要工具、执行步骤、验证和输出。较长的组件/API 参考放在该 Skill 的 `references/` 中。

不要在 Skill 中复制：

- 全局架构、产品、安全或可靠性不变量；这些属于 `ARCHITECTURE.md` 或 `docs/`。
- 某个复杂任务的实施历史；这些属于 `docs/exec-plans/`。
- 可由 lint、类型检查、测试或 CI 自动执行的规则。

## 维护要求

1. 先搜索现有 Skills，避免重叠工作流。
2. 让 description 能据任务类型明确匹配，避免泛化为“所有开发工作”。
3. 使用仓库中真实存在的路径、命令和工具；引用资料须可访问。
4. 为有副作用或高风险的流程写出验证和恢复条件。
5. 修改已安装 Skill 或其来源记录时，同步审查 `skills-lock.json`，但不要手工伪造来源或哈希。
6. 将稳定的使用路由简短加入 `AGENTS.md`；不要复制完整工作流。

## 验收

评审一个新增或修改的 Skill 时，确认它能被正确触发、步骤没有重复长期文档、引用路径存在，并且验证步骤确实可在当前仓库执行。若 Skill 引入新的长期架构或安全规则，应先更新对应知识文档。

相关知识见 [Skills 治理](./skill.md)。
