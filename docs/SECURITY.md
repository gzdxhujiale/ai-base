# 安全契约

## 当前安全模型

这是未接入服务端的客户端原型。仓库没有认证、授权、会话、数据库、密钥配置、文件上传或外部 API；静态企业名称、用户、菜单与 AI 建议均为演示内容。因此当前不存在可实现的租户隔离、角色权限或服务端审计模型。

浏览器是唯一已实现的信任边界：进入 `src/`、URL 或静态资源的内容最终可能被交付给客户端。客户端状态和显示内容不能充当授权或数据保护机制。

## 当前安全不变量

| 不变量 | 原因 | 当前执行方式 |
| --- | --- | --- |
| 不在客户端代码或静态资源中硬编码密钥、令牌或真实企业数据。 | 构建产物对浏览器可见。 | 文档与评审；尚无 secret scan。 |
| 将用户输入、URL 值、未来远端数据和 AI 输出视为不可信。 | 当前和未来的边界都可能引入控制内容。 | 文档与组件实现审查。 |
| 未接入真实 AI 或企业数据前，不声明它们已受权限保护。 | 目前没有身份或授权实现。 | 原型表述与设计审查。 |

当前代码没有渲染富文本或 Markdown。若未来添加，必须先定义并实现允许列表、转义与内容来源边界；不要假设普通 React 文本渲染可自动覆盖新渲染路径。

## 尚未定义的边界

以下能力均没有实现或选型，不能从当前文档推导细节：认证方式、会话失效/登出、角色与数据级授权、租户隔离、CSRF/CORS、速率限制、输入校验、密钥注入/轮换、审计保留、CSP 与依赖扫描。

## 安全敏感变更

下列变更必须先建立服务边界并更新 `../ARCHITECTURE.md`、`RELIABILITY.md` 和 ExecPlan：

- 身份、会话、角色、权限、租户或真实企业数据；
- AI 请求代理、上下文选择、提示词/输出处理或审计；
- 外部 URL、第三方 API、文件上传或富文本/Markdown 渲染；
- 将令牌、环境配置或任何敏感数据带入构建、日志或客户端状态。

设计时须明确每个边界的认证、授权、输入验证、输出处理和日志限制；认证不等于授权，浏览器侧隐藏 UI 不等于权限校验。

## 验证与已知缺口

可执行检查仅有 `pnpm build` 与 `pnpm lint`，不存在安全测试、依赖扫描或 secrets 扫描。`pnpm lint` 当前受 `.vitepress/cache` 生成文件影响而失败，不能视为安全检查。安全能力接入时，应把真实验证命令写入相关 ExecPlan，并在 `QUALITY_SCORE.md` 更新证据。
